# Synthetic PDF self-tests

These five compact PDFs exercise a narrow part of the experimental Rust alpha: finite insulated wall placement and finish visibility through later PDF paint. They are authored test diagrams, not real building plans or training data from clients.

Each file is one 240 by 200 unit page. An insulation assembly with two rows has thin closed finishes and a separate hinged door symbol for plan context. The alpha must distinguish observed wall geometry from material that is safe to place.

| PDF | Expected result in the verified reference and public alpha |
| --- | --- |
| `01-insulated-wall.pdf` | One finite ready wall assembly; both finish bands certified. |
| `02-background-then-local-faces.pdf` | Same ready assembly. Normal background paint precedes both complete local faces; earlier remote closures remain protected. |
| `03-erased-finish.pdf` | Full assembly stays under review because later white paint erases part of a finish and its outer boundary. |
| `04-erased-remote-closure.pdf` | Full assembly stays under review because a required remote contour closure was erased. Later local faces cannot repair it. |
| `05-compound-paint-erases-closure.pdf` | Full assembly stays under review. A second internal subpath boundary does not make an opaque painted union transparent. |

In both alpha tests, the first two PDFs export one ready barrier of thickness 20 over native drawing bounds `[22,100,178,120]`; the last three export no ready barriers. The separate door symbol is detected in all five. Independently valid core material may remain eligible in later versions even when a full assembly is withheld.

Run a sample from the Windows runtime package root:

```powershell
.\openplantrace-rs.exe scan .\samples\self-test\01-insulated-wall.pdf --out .\scan-sample-01
```

Inspect `scan.json`, `placement.json` and the SVG overlays in the output directory. A ready finite wall is not a claim that the entire page is ready for unattended placement or that a house boundary is complete.

The samples paint vector geometry. They do not benchmark raster or mixed PDFs, window detection, furniture recognition, real-project accuracy, or a doorway cut through the selected assembly. The nearby door is context only. Scan outputs still require review.

## Provenance and redistribution

The PDF bytes are reproduced by the included standalone `regenerate.py`, using only explicit points, lines, a mathematical batt pattern, a quarter-circle approximation and literal fill operations. It reads no source drawings or external assets. No client PDF, project geometry, project text, font file or third-party artwork is included.

The shared PDF template retains an unused 4 by 4 pure white RGB image generated by code and a simple gray rectangle form. Neither comes from an external image. The five page content streams do not invoke those resources. The PDFs have no document information metadata, XMP, attachments, links, scripts or embedded fonts.

The samples and generator are distributed under the repository's **BSD-2-Clause** notice, copied into `LICENSE`. Retain that notice when redistributing them. `provenance.json` and `SHA256SUMS.txt` identify the audited bytes.

From the `samples/self-test` directory, an optional byte-for-byte regeneration check is available independently of the Rust scanner:

```powershell
python .\regenerate.py --check
```

The reference run used Windows scanner engine `0.12.32-alpha.20`, original executable SHA256 `2853c4d28bf591d2a2210f62ecdaee4eb200937f2394b12d9bbdcf2c06a4ec3f`, before public path remapping. The independently verified public executable has SHA256 `6dd19a8e61cfce657cb042793c6b41f9cbece582ca47b4d5a8d9f74f8cd89827`. All five exact PDFs produced matching ready-barrier counts `[1,1,0,0,0]` on both executables. Independent release verification also passed 130 paired/sample scans and 390 public validator checks. No broad accuracy or performance claim follows from these small controls.
